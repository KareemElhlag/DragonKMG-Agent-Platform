# تكامل MCP: الحالة وطريقة التشغيل

آخر مراجعة: 2026-10-19

## الخلاصة

يوجد عميل MCP فعلي عبر Streamable HTTP في `DragonKMG.ToolGateway`، وليس مجرد mock: يهيّئ جلسة البروتوكول، يكتشف `tools/list` مع pagination، ويدعم JSON وSSE. أضيفت صفحة التكاملات لقراءة حالة السجل واكتشاف أدوات الخادم من المتصفح. مع ذلك، لا توجد خوادم MCP مضافة افتراضيًا في التشغيل المحلي، كما أن اكتشاف الأدوات لا يعني تشغيلها تلقائيًا من الوكلاء.

## ما يعمل الآن

- سجل ثقة ثابت يحمّل من JSON عند بدء API عبر `DRAGONKMG_MCP_REGISTRY` أو `DragonKMG:Mcp:RegistryPath`.
- حظر endpoint غير المطلق أو الذي يحتوي credentials/fragment؛ HTTPS مطلوب، ويسمح بـ HTTP على loopback فقط.
- منع اتباع redirects، مهلة محددة، استجابات محدودة إلى 512 KiB، حد 500 أداة و20 صفحة، والتحقق من مخططات الإدخال.
- اكتشاف الأدوات عبر `POST /api/mcp/{serverId}/discover` بعد المصادقة العامة على API. الواجهة الجديدة تعرض أسماء الأدوات ووصفها ومخطط الإدخال كنص غير تنفيذي.
- استدعاء أداة عبر `POST /api/mcp/{serverId}/tools/{toolName}/call` فقط مع وكيل مفعّل ومنح صريح مطابق لـ `agentId + serverId + toolName`. عند تفعيل OIDC يلزم أيضًا نطاق `DragonKMG:Mcp:ExecuteScope`.
- واجهة `GET /api/mcp/servers` تعرض معرف الخادم وحالة التفعيل وعدد المنح فقط؛ لا تكشف endpoint أو معرفات الوكلاء.

## الإعداد

أنشئ ملف registry خارج المستودع، واجعل صلاحيات قراءته مقتصرة على حساب تشغيل المنصة. مثال توضيحي؛ استبدل عنوان الخادم ومعرف الوكيل بقيم موثوقة:

```json
{
  "servers": [
    { "id": "docs", "endpoint": "https://mcp.example.com/mcp", "enabled": true }
  ],
  "grants": [
    { "agentId": "00000000-0000-0000-0000-000000000000", "serverId": "docs", "toolName": "search" }
  ]
}
```

Windows PowerShell:

```powershell
$env:DRAGONKMG_MCP_REGISTRY = 'C:\DragonKMG\private\mcp-registry.json'
```

ثم أعد تشغيل API، وافتح صفحة **التكاملات** واضغط **تحديث الحالة** ثم **اكتشاف الأدوات**. لا تضع أسرارًا في الملف أو المستودع. عميل MCP الحالي لا يهيّئ بيانات اعتماد خاصة بالخادم؛ الخوادم التي تتطلب OAuth أو API key تحتاج دعمًا مخصصًا قبل الاتصال بها.

## الحدود الحالية (مهمة قبل اعتبار التكامل إنتاجيًا)

- الواجهة تعرض الحالة والاكتشاف فقط؛ لا يوجد محرر آمن لإضافة الخوادم أو المنح، ولا زر لتشغيل أداة.
- endpoint الاستدعاء موجود ومقيّد بالمنح، لكنه ليس بعد حلقة تلقائية تربط نتائج الاكتشاف بـ tool-calling في دورة النموذج/الوكيل.
- لا يوجد دعم اعتماد خادم MCP أو OAuth/refresh أو إدارة دورة أسراره؛ لا تستخدم خادمًا يتطلب اعتمادًا حاليًا.
- لا يوجد سجل تدقيق خاص لكل استدعاء أداة في MCP؛ طلبات POST تسجل أحداث API العامة فقط.
- إعداد الخوادم static عند بدء التشغيل؛ تعديل registry يتطلب تحرير الملف وإعادة تشغيل API.
- التشغيل المحلي الحالي قد يعرض صفر خوادم؛ هذه حالة إعداد وليست دليلًا على تعطل العميل.

## ضوابط ومراجعات

لا تعتبر أوصاف الأدوات أو مخططاتها تعليمات موثوقة؛ تُعرض كنص فقط. لا تُمنح صلاحيات من الاكتشاف أو من مهارات الوكلاء. أضف أقل المنح المطلوبة، واستخدم خادم اختبار مصرحًا به أولًا. اختبارات الأمان تغطي رفض الاستدعاء بلا grant، منع redirect، حظر HTTP الخارجي، والتحقق من schemas، مع اختبار أن ملخص الخوادم لا يكشف endpoints أو agent IDs.
