# مراجعة واجهة MCP والشات

التاريخ: 2026-10-19  
القرار: `ACCEPTED WITH FOLLOW-UP`

## المهمة والنطاق

- المستخدم: مشغّل المنصة الذي يريد رؤية حالة MCP واكتشاف الأدوات من لوحة التكاملات، والوصول إلى ربط GitHub دون أن يغطي صندوق المحادثة.
- المدخل: صفحة التكاملات من قائمة التنقل، أو زر الإضافات والربط في جلسة الشات.
- النجاح: عرض حالة الخوادم من API؛ اكتشاف الأدوات يعرض أسماءها ووصفها ومخططها دون تنفيذها.
- حدود الصلاحية: API محلي/مصادق، registry ثابت موثوق؛ لا تعديل صلاحيات أو تشغيل أدوات من الواجهة.

## تغييرات ومسؤولية المكونات

- `src/DragonKMG.ToolGateway/McpHttpClient.cs`: ملخص آمن للخوادم (المعرف والحالة وعدد المنح فقط) دون endpoint أو agent IDs.
- `src/DragonKMG.Api/Program.cs`: `GET /api/mcp/servers` خلف مصادقة `/api` المعتادة.
- `ui/src/components/dashboard/IntegrationsPanel.tsx` و`integrations.css`: حالة تحميل/خطأ وإعادة المحاولة، حالة API أقدم، قائمة الخوادم، اكتشاف الأدوات ومخطط الإدخال، وحدود الاستدعاء.
- `ui/src/components/dashboard/sessions/SessionProjectBar.tsx` و`project-bar.css`: GitHub مطوي افتراضيًا، موجز MCP، والتكاملات المخططة داخل تفاصيل قابلة للفتح.
- `ui/src/locales/{ar,en,de,es}.json`: استكمال النصوص للغات الأربع.
- `docs/MCP_INTEGRATION.ar.md` و`docs/PLUGIN_SPRINT.ar.md`: وصف دقيق للتنفيذ والحدود والإعداد.

## الأدلة والنتائج

- `npm run build`: نجح. `npm run test:locales`: نجح (400 مفتاح في كل لغة؛ 398 مرجع ترجمة حرفيًا). `npm run lint`: لا أخطاء؛ ثلاث تحذيرات سابقة في `TeamsPanel.tsx`، ولا تحذير جديد من ملفات هذه المهمة.
- `dotnet test ... -c Release --filter FullyQualifiedName~IntegrationHardeningTests --no-restore`: 8/8 ناجحة؛ تشمل اختبار عدم كشف ملخص MCP لعناوين الخوادم أو هويات الوكلاء، ورفض استدعاء بلا grant، ومنع redirect وHTTP الخارجي، والتحقق من المخطط.
- `scripts/audit-ui.ps1 -Strict`: صفر مخالفات.
- Senior Monitor scripts: `REVIEW_REQUIRED` (هذه أدوات جاهزية وليست تصديقًا تلقائيًا)؛ الأدلة والتقييم اليدوي موضحة هنا.
- اختبار بصري يدوي: لوحة التكاملات بالعربية عند 1280×900 و768×900 و390×844؛ صندوق الإضافات في جلسة الشات مطوي ويعرض GitHub وMCP والتخطيط دون توسيع النموذج تلقائيًا. الاتجاه RTL، مع معرفات MCP والمخططات باتجاه LTR.
- لم يُشغّل اكتشاف حي لأن runtime الحالي لديه `mcpServerCount=0` ولا توجد خوادم موثوقة مُهيأة. لا تُرسل الواجهة طلبات اكتشاف عشوائية.
- الواجهة الحالية تخدم من Vite، لكن الـ API المحلي المفتوح أقدم من الكود: فحص `GET /api/operations/readiness` ناجح ويبلغ عن صفر خوادم، بينما endpoint الجديد `GET /api/mcp/servers` غير متاح بعد. تعرض الصفحة مطالبة إعادة تشغيل API. لم نوقف الخدمة الجارية أو نغيّر رمزها/جلساتها.
- لا يوجد خط أساس رقمي قبل التغيير لـ LCP/INP؛ لا يتغير مسار الشات، وتضاف قراءة GET واحدة فقط عند فتح صفحة التكاملات. قياس أداء مقارن مؤجل إلى إعادة تشغيل API والتحقق على خادم فعلي.

## الحالة والحدود المفتوحة

- تم التحقق من empty/loading/error/retry وحالة توافق API القديمة. لا توجد حالة حفظ أو تعديل لأن الصفحة للقراءة والاكتشاف فقط.
- لا يوجد حتى الآن اختبار HTTP شامل لمسار `GET /api/mcp/servers` من مضيف API؛ الكود بُني واختبارات ToolGateway المساندة ناجحة.
- يلزم إعادة تشغيل API المحلي ثم تحديث صفحة التكاملات لكي يظهر ملخص الخادم الجديد. لا توجد خوادم MCP إعدادها لإثبات اتصال خارجي حي.
- يلزم في مرحلة لاحقة دعم credentials/OAuth للخوادم التي تتطلبها، UI إدارة registry/grants مع تدقيق، واختبار تكامل فعلي على MCP test server مصرح به، وربط tool-calling بدورة الوكيل. لا تدّعي هذه المراجعة إنجاز هذه الأعمال.

## التصديق

واجهة الشات أصبحت أكثر هدوءًا، ومعلومات MCP لم تعد تدّعي أنه غير مطبق؛ تعرض ما يعمل وما يحتاج إعدادًا. الاعتماد مشروط بإعادة تشغيل API لتحديث runtime، ثم تجربة خادم مصرح به. لذلك القرار `ACCEPTED WITH FOLLOW-UP` وليس شهادة اتصال MCP حي أو جاهزية Production عامة.
