# حوكمة سير عمل الوكلاء والمحرر المرئي

## دورة التنفيذ

1. يختار المستخدم سير العمل من صفحة Workflows.
2. كل عقدة تمثل وكيلًا واحدًا، وترتيبها يحدد ترتيب التنفيذ.
3. الروابط تمثل انتقال الأدلة من مرحلة إلى المرحلة التالية.
4. قبل التنفيذ يتحقق النظام من ملكية المراحل لسير العمل، عدم وجود دورات، وجود وكيل مفعّل، وصلاحيات الموافقة.
5. المرحلة التي تتطلب موافقة تتوقف Fail-Closed حتى وجود موافقة صريحة.
6. تُحفظ نتيجة كل مرحلة كـ `WorkflowRun` ولا تُعتبر المرحلة ناجحة بلا دليل محفوظ.

## نموذج البيانات

- `WorkflowDefinition`: الاسم، الإصدار، وحالة التفعيل.
- `WorkflowStage`: الوكيل، الموضع، checklist، الدليل المتوقع، ومتطلب الموافقة.
- `WorkflowEdge`: انتقال موجه بين مرحلتين.
- `WorkflowRun`: حالة التشغيل، الخطأ، ووقت البداية والنهاية.

## الأمان

- لا يسمح المحرر بدورة في الرسم البياني.
- لا يسمح بمرحلة بلا وكيل أو بوكيل غير مفعّل.
- لا تُمنح صلاحيات أدوات من خلال الرسم؛ الصلاحيات تظل في Tool Grants وApproval Engine.
- الروابط لا تنقل محتوى ملفات أو أسرارًا تلقائيًا.
- أي مرحلة حساسة تتطلب موافقة صريحة، وتفشل مغلقًا عند غيابها.

## واجهة المستخدم

تظهر صفحة الإعدادات لوحة مرئية بعقد مرتبة وروابط بينها، مع اختيار سير العمل، الإصدار، عدد المراحل والروابط، وعلامة واضحة للمراحل التي تحتاج موافقة. التصميم يدعم RTL، التمرير الأفقي على الشاشات الصغيرة، وحالات التحميل والخطأ.

## حدود النسخة الحالية

المحرر المرئي الحالي يعرض البنية المحفوظة ويجعل اختيار سير العمل واضحًا. تحرير العقد بالسحب والإفلات، إضافة الروابط بصريًا، وسجل التشغيل الحي هي خطوات لاحقة، ويجب تنفيذها عبر API والتحقق نفسه لا عبر حالة واجهة محلية فقط.
