# فريق Nexus Feature Full Production

## الهدف

قالب فريق افتراضي لبناء ميزات NexusCore عبر خط إنتاج متتابع قابل للتدقيق: تخطيط، تنفيذ، اختبار وتوافق، UX حسب المنصة، أداء، تدقيق شامل، أمن، ثم قرار جاهزية موثق. يُنشأ من صفحة **Teams** بعد اختيار اتصال ونموذج فعليين، ويُحفظ كفريق عادي قابل للتعديل، ويمكن تعيينه كفريق الجلسة أو اختياره لطلب واحد.

## خط الإنتاج

| الترتيب | العضو | الوضع | ناتج المرحلة |
|---|---|---|---|
| 1 | Nexus Feature Planner | Plan only | نطاق، افتراضات وأسئلة لازمة، خريطة ملفات وحدود، مخاطر ومعايير قبول؛ لا يكتب كودًا. |
| 2 | Nexus Feature Implementer | Execution | التغييرات المحددة فقط، اختبارات مناسبة، وفصل الدليل المنفذ عن المقترح. |
| 3 | Nexus Feature Test & Compatibility | Review | يربط معايير القبول بالاختبارات، ويقدم نتائج التشغيل والتوافق الفعلي بما فيها حالات الفشل والتخطي. |
| 4 | Nexus Feature Platform UX | Review | يراجع UX للويب وFlutter؛ يحدد المنصة من ملفات المشروع، ويستخدم معايير الواجهة الملائمة فقط. |
| 5 | Nexus Feature Performance | Review | تحليل التعقيد والذاكرة/التخصيصات والتزامن والأحداث، مع baseline وقياس فعلي أو `UNVERIFIED`. |
| 6 | Nexus Feature Master Auditor | Review | تدقيق المتطلبات والمعمارية والاختبارات وتكاملات البيانات، مع نتائج مرتبة ودليل لكل ادعاء. |
| 7 | Nexus Feature Security Reviewer | Review | مراجعة دفاعية للصلاحيات والعزل والأسرار والتحقق من المدخلات وسطح الهجوم. لا يشغّل اختبارات نشطة أو أدوات خطرة تلقائيًا. |
| 8 | Nexus Feature Release Certifier | Review | يراجع مخرجات المراحل كلها ويصدر نسبة الجاهزية، قرارًا، المتبقي، وسبب كل درجة. لا ينفذ ولا يغير قرارات الوكلاء السابقين. |

يعمل الفريق افتراضيًا **بالتسلسل**؛ كل مرحلة تتلقى الطلب الأصلي ومخرجات سابقة محدودة، وتُحجب المراحل التالية إذا فشلت مرحلة. يمرر المنفذ آخر 12,000 محرف من المخرجات السابقة لكل عضو، ويحتفظ بمحادثة الفريق حتى 64,000 محرف؛ مهلة تشغيل الفريق الحالية 90 ثانية. هذه حدود أحرف وليست عداد tokens.

خريطة المهارات المقصودة:

- التخطيط والتنفيذ: `kmg-engineering-standard` (KMG) + `nexus-feature-performance`.
- الاختبارات والتوافق: KMG + `nexus-master-audit-skill`.
- تجربة المنصة: `nexusecore-ui-ux` + `flutter-architect-review` متاحان للوكيل؛ يحدد نطاق المراجعة وفق ملفات المشروع ولا يطبق معايير Flutter على تطبيق ويب فقط.
- الأداء: KMG + `nexus-feature-performance`.
- التدقيق الشامل: KMG + `nexus-master-audit-skill`.
- الأمان: KMG + `cyber-kmg-security`.
- التصديق: KMG + `nexus-master-audit-skill` + `cyber-kmg-security`.

لا تمنح المهارات صلاحيات أدوات. كل أعضاء الفريق يبدأون بلا tool grants؛ صلاحية قراءة الملفات أو أي تكامل تُمنح مستقلة وتخضع لسياسة المنصة وموافقة المستخدم.

## احتساب الجاهزية

النسبة تقدير مبني على أدلة هذه الدورة، وليست قياسًا آليًا لاكتمال المنتج. يوزع المصادق 100 نقطة على: المتطلبات والتخطيط (10)، المعمارية (15)، التنفيذ (20)، تجربة الاستخدام والمنصة (10)، الأداء (10)، الاختبارات (15)، الأمان (15)، التشغيل والمراقبة والتراجع (5). تُمنح كل فئة: كاملة = وزنها، جزئية = نصف الوزن، فاشلة أو غير متحققة = صفر. لا تُستبعد فئة إلا إذا كانت خارج النطاق مع سبب. الحساب: مجموع النقاط المستحقة ÷ مجموع الأوزان المنطبقة × 100، مقربًا للأسفل.

يعرض التقرير لكل فئة: الوزن والنقاط والحالة والدليل أو الأمر المنفذ. الاختبار الذي لم يُشغّل، الادعاء بلا دليل، وأي مخاطرة مفتوحة تبقى `UNVERIFIED`/`BLOCKED` ولا تُحسب نجاحًا. لا تعني 100% ضمان انعدام العيوب أو الأمان المطلق؛ تعني فقط اجتياز البوابات المدرجة بأدلتها ضمن النطاق المحدد. إذا تعذر إثبات نتيجة، لا يصدر الفريق `CERTIFIED`.

## الحدود الحالية

- تنفيذ الفريق تسلسل استدعاءات نماذج، وليس تشغيلًا متوازيًا؛ تشغيل كل الأعضاء قد يستهلك حتى ثمانية استدعاءات نموذج للطلب الواحد، لذلك يُستخدم هذا القالب للميزات ذات الأثر الكبير، وتبقى المهام الصغيرة على وكيل واحد.
- إن تعطلت عملية الإنشاء قبل حفظ الفريق كاملًا، يمكن إعادة المحاولة لاستكمال الأعضاء والمهارات الناقصة مع إبقاء تخصيصات الأعضاء الموجودة؛ أما الفريق المحفوظ كاملًا فيُعاد كما هو عند التكرار.
- مهارات الويب وFlutter المعيّنة للوكيل تُحمّل كتعليمات معًا؛ لا يوجد حاليًا محرك routing شرطي يحذف استدعاء مهارة غير مطابقة تلقائيًا. على الوكيل أن يقصر مراجعته على المنصة المثبتة بالأدلة، ولا يدّعي تطبيق معايير Flutter على الويب فقط أو العكس.
- النموذج والاتصال اللذان يختارهما المستخدم يُستخدمان كبداية لأعضاء الفريق؛ يمكن تعديل ربط كل عضو لاحقًا. لا تُخترع مفاتيح أو نماذج.
- وضع `Execution` لا يمنح الوكيل تنفيذ أوامر النظام. لا تُنفذ تغييرات على مستودع حقيقي إلا عبر قدرات مضيف موصولة فعلًا، وبصلاحياتها الصريحة. إذا لم تكن أدوات التنفيذ متاحة، يعيد الوكيل مقترحات/patches ويصرّح بذلك.
- لا يُعد تشغيل النموذج بديلًا عن CI أو اختبارات المتصفح أو مراجعة بشرية للمخاطر التجارية والمالية.

## التشغيل والاستخدام

1. من **Skills** تأكد أن مهارات الفريق المطلوبة موجودة ومفعّلة؛ يمكن تعديل نصوصها أو استبدالها بمهارات المشروع.
2. من **Teams** اختر قالب **Nexus Feature Full Production**، اتصال مزود مفعّلًا ونموذجًا مسجلًا ومفعّلًا، ثم أنشئ الفريق المحفوظ. الطلب يتحقق من هذه المتطلبات ويرفض الإعداد الناقص؛ القالب لا يضعه تلقائيًا كفريق جلسة افتراضي.
3. إنشاء القالب تكراري عند وجود الفريق المطابق: يعيد الفريق والأعضاء الحاليين ولا يستبدل اتصالاتهم أو تعليماتهم أو إعداداتهم المخصصة. تعارض اسم عضو موجود مع دور/وضع غير متوافق يرفض العملية بدل تعديل عضو مخصص بصمت.
4. راجع ترتيب الأعضاء والمهارات من صفحات الإدارة، ثم اختر الفريق للجلسة من إعدادات الجلسة أو وجهه لأمر واحد. إن غاب الفريق الافتراضي ولم يحدد المستخدم فريقًا، تطلب المنصة اختيارًا بدل التخمين.
5. اقرأ مخرجات المصادق: النسبة لا تُقبل وحدها دون دليل الفئات والحدود المفتوحة.
