## ضوابط تحققت في الكود والاختبارات

- OIDC: تحقق من issuer/audience والتوقيع والعمر، وHTTPS للـmetadata؛ Production يرفض الإقلاع دون OIDC وscope مطلوب. عند تفعيل OIDC لا يعمل الرمز المحلي كمسار بديل.
- MCP: سجل خوادم محلي ثابت، HTTPS أو HTTP على loopback فقط، رفض التحويلات، حدود للحجم/الوقت، والتحقق من مخطط JSON. التنفيذ يتطلب وكيلًا موجودًا ومفعّلًا وGrant مطابقًا، إضافةً إلى scope تنفيذ MCP عند استخدام OIDC.
- النسخ: نسخة SQLite online مؤقتة، فحص `integrity_check`، ثم نقل ذري إلى الاسم النهائي. مصدر مفقود لا يُنشأ تلقائيًا. اختبار الإنشاء والتحقق واختبار المصدر المفقود نجحا.
- اختيار PostgreSQL غير مدعوم يفشل مبكرًا بدل تبديل التخزين بصمت إلى SQLite.
- ملفات الأدلة الأمنية تُستثنى من Git وDocker.

## المتبقي والمخاطر

1. **PostgreSQL غير منفذ**؛ التخزين الحالي SQLite، ولا يوجد تحقق ترحيل أو تكافؤ بيانات على PostgreSQL.
2. **لا توجد هوية متعددة المستخدمين أو عزل مستأجرين/أدوار**. OIDC يثبت token ويشترط scope، لكنه لا يربط المستخدم بوكيل/مستأجر؛ حامل scope MCP يستطيع اختيار أي وكيل ممنوح. لا تعرض واجهات إدارة MCP لمستخدمين غير موثوقين.
3. **MCP لا يدعم أسرار اتصال الخادم** ولا يربط استدعاء الأداة بعد بمسار موافقات وآثار أعمال. اقتصر الاختبار على خادم HTTP وهمي داخل وحدة الاختبارات.
4. **استعادة النسخ غير متاحة**، ولا توجد سياسة احتفاظ أو تشفير نسخ احتياطية. لا تعتمد عليها كخطة تعافٍ قبل إضافة واختبار الاسترجاع.
5. **فحص الاعتماديات الآمن غير مكتمل**: جرى حصر 13 manifest، لكن لم يُشغّل ماسح advisory خارجي/متصل؛ لا تُفسر نتيجة الحصر على أنها خلو من CVEs.
6. **اختبار الاختراق النشط محجوب** لغياب تحديد hostname/port والحسابات والأدوار والوقت والحدود. كما أن ملف `strix-offensive-validation.md` الذي تشير إليه المهارة غير موجود في نسختها المحلية؛ لم يُشغّل أي exploit أو فحص شبكي.
7. لم يُختبر الاتصال الحي بمزود OIDC، ولم يُشغّل API في وضع Production؛ لذلك هذه النتائج لا تثبت صلاحية النشر العام.
