# تجربة GitHub وتحسين متابعة التنفيذ — 2026-10-15

## النطاق والحالة

ميزة محلية للقراءة فقط: ربط حساب GitHub برمز Fine-grained PAT، عرض المستودعات المتاحة للرمز ومنها الخاصة، واختيار مستودع لمجلد المشروع. لا clone أو قراءة محتوى أو push أو نشر أو grants تلقائية. OAuth/GitHub App وتعدد حسابات المستخدمين ليست ضمن هذا التنفيذ.

اختار المستخدم الحساب والمستودعات الخاصة؛ لم يقدم رمزًا ولم يُستخرج أي اعتماد من تطبيق آخر. لذلك **تجربة حسابه الخاص الحية لم تنفذ بعد**؛ شاشة الإدخال جاهزة له. تفاصيل الاستخدام والصلاحيات في `GITHUB_INTEGRATION.ar.md`.

## التمرير والتنفيذ

- الويب يحفظ معرف الرسالة الظاهرة وإزاحتها عند تحديث التاريخ وتحميل الأقدم وتغيّر حجم المحتوى. لا يجر القارئ للأسفل؛ المتابعة تلقائية فقط ضمن80px من الأحدث، مع زر انتقال صريح.
- مراقبة ارتفاع المحتوى والنافذة معًا، وبقاء الرسائل أثناء تحديثها. تبقى صلاحيات الملفات والإرسال للمزود مستقلة.
- المراحل الفعلية: التحقق من سياق الملفات، بدء عضو باسم وموديل وترتيب، انتهاء العضو، حفظ الرد، أو فشل/إلغاء. لا عرض لتفكير النموذج الخاص ولا ادعاء اختبارات لم تحدث.
- الويب يقرأ الحالة بطلبات غير متداخلة كل800ms، بمهلة3s، ومعرف يطابق الطلب الحالي. فشل قراءة الحالة لا يعيد البرومبت ولا يحجز مربع الكتابة.
- الحالة تشغيلية مؤقتة بحد32 حدثًا وآخر10 دقائق وبحد1024 جلسة في عمليةAPI؛ ليست سجل تدقيق دائمًا ولا بثًا بين العمليات. الرسائل وAgentRuns هما السجل الدائم.CLI يعرض نفس مراحل خدمة التنفيذ مباشرة عبر طابور آمن، ويظل التاريخ مشتركًا عند استخدام نفس قاعدة البيانات.
- الترمينال يدعمPgUp/PgDn أثناء التنفيذ، ويحافظ على موضع القراءة عند وصول مراحل جديدة. الواجهة العائمة لها مقابل أوامر، وليست رسومات متطابقة داخل الترمينال.

## الأمان والتراجع

المراجعة شملت الخادم المحلي ومساراته وكودGitHub باختباراتHTTP/Vault وهمية، لا اختبارات اختراق علىGitHub. فحص المصدر الآمن أعاد3 مطابقات محتملة راجعت كإيجابيات كاذبة (نصSecret فيCLI ومتغيرا اتصالSQLite محسوبان)،صفر أنماطDocker خطرة،13 ملف اعتماد. الأدلة الخام فيsecurity-temp المهمل منGit وDocker. هذا ليس فحصCVE شاملًا أو ضمانًا خلو المشروع من الأسرار.

بصمة الاعتماد تعزل روابط المستودعات عند تغيير الرمز؛ طلب قديم لا يكشف اسم مستودع حساب سابق. تضارب عملياتAPI/CLI قد يتطلب إعادة اختيار المستودع. الخزنة الحاليةWindows DPAPI فقط، وحساب واحد لكل مستخدم نظام محلي، وليس عزلًا متعدد المستأجرين.

التراجع: الرجوع للكود السابق مع الإبقاء علىSQLite؛ لا حذف للمحادثات. فصلGitHub يمسح الرمز والروابط محليًا ولا يسحب الرمز منGitHub؛ السحب يتم من إعداداتGitHub. لا تُدخل الرموز في الشات أو سطر الأوامر.

## الاعتماد

قرار المراجع المستقل: `CERTIFIED_WITH_RESIDUE` للتجربة المحلية علىWindows فقط. نُفذت مراجعة أمنية ومراجعةUX مستقلة عن المنفذ،واختبارات المصدر وHTTP المذكورة. المستخدم مسؤول عن إدخالPAT لاختبار حسابه؛ المتبقي بقيادة المنظم قبل النشر العام: عزل متعدد المستخدمين،OS Vault لأنظمة أخرى،اختبارات المتصفحات وقارئات الشاشة،وقياسP95. لا يعني هذا جاهزية إنتاجية عامة أو اعتمادًا أمنيًا شاملًا.
