# تشغيل DragonKMG محليًا

هذا الدليل يشغّل لوحة التحكم والـAPI المحلي من نسخة المستودع على Windows أو macOS أو Linux. أول تشغيل قد يستعيد حزم .NET وواجهة الويب من ملفات القفل؛ لذلك يحتاج اتصال إنترنت. التشغيل محلي ومناسب للتجربة والتطوير، وليس إعدادًا لتعريض المنصة للإنترنت أو لاستخدام عدة مستخدمين.

## من نسخة GitHub جديدة

نزّل المستودع وافتح مجلد التطبيق:

```text
git clone https://github.com/KareemElhlag/DragonKMG-Agent-Platform.git
cd DragonKMG-Agent-Platform/dragonkmg
```

المتطلبات: .NET 9 SDK وNode.js 20.19 أو أحدث ضمن 20.x، أو 22.12 فأحدث. ثبّت Node مع npm؛ وعلى macOS/Linux يلزم `curl` لفحص جاهزية الخدمات. لا يحتاج هذا المسار إلى تثبيت NuGet global tool.

### Windows

افتح PowerShell داخل مجلد `dragonkmg`:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\start-local.ps1
```

للتأكد من المتطلبات واختيار قاعدة البيانات من دون تشغيل الخدمات:

```powershell
.\scripts\start-local.ps1 -CheckOnly
```

### macOS وLinux

من Terminal داخل مجلد `dragonkmg`:

```bash
bash scripts/start-local.sh
```

للفحص فقط:

```bash
bash scripts/start-local.sh --check-only
```

السكربت يتحقق من الإصدارات، ويثبت حزم الواجهة بواسطة `npm ci` من `package-lock.json` إذا لم تكن مثبتة، ثم يشغّل الـAPI والواجهة على loopback فقط ويفتح `http://127.0.0.1:5173/`. عند أول تشغيل، انتظر ظهور `DragonKMG is ready` في نافذة التشغيل؛ انسخ رمز الوصول المؤقت الظاهر فيها إلى نموذج الوصول داخل اللوحة. الرمز عشوائي لكل تشغيل، ولا يُكتب في ملف أو يُمرر إلى الواجهة. أوقف الخدمات بـCtrl+C في macOS/Linux أو بإغلاق نافذتي API وDashboard في Windows.

للدخول إلى واجهة الترمينال أيضًا، استخدم `-WithCli` على Windows أو `--with-cli` على macOS/Linux. ستستخدم الواجهة والـCLI قاعدة SQLite نفسها.

## استمرارية الجلسات والبيانات

يمرر المشغّل مسار قاعدة SQLite واحدًا إلى الـAPI والـCLI. على نسخة موجودة، يختار أحدث ملف محلي بين قاعدة API الموجودة في `src/DragonKMG.Api/bin/{Debug,Release}/net9.0/dragonkmg.db` وقاعدة المستخدم الافتراضية؛ وفي نسخة جديدة يبدأ بقاعدة المستخدم الافتراضية. مسارها على Windows هو `%LOCALAPPDATA%\DragonKMG\dragonkmg.db`، وعلى macOS هو `~/Library/Application Support/DragonKMG/dragonkmg.db`، وعلى Linux هو `${XDG_DATA_HOME:-~/.local/share}/DragonKMG/dragonkmg.db`.

لا يدمج المشغّل قواعد بيانات سابقة ولا يحذفها ولا يستبدلها تلقائيًا. إذا كانت لديك جلسات في أكثر من قاعدة، احتفظ بنسخة من كل ملف قبل أي نقل، واختر يدويًا عبر `DRAGONKMG_DB_PATH` بعد الإيقاف. تجنب تشغيل أكثر من نسخة على قاعدة SQLite نفسها في وقت واحد. استخدم النسخ الاحتياطي قبل الترقية أو التجارب التي تغيّر بيانات مهمة.

المنافذ الافتراضية `5188` للـAPI و`5173` للواجهة. إذا كان أحدها مشغولًا يتوقف المشغّل برسالة، ولا ينهي أي عملية قائمة. أغلق الخدمة الأخرى أو أوقفها بنفسك ثم أعد التشغيل. يمكن إيقاف فتح المتصفح تلقائيًا على macOS/Linux بمتغير `DRAGONKMG_NO_BROWSER=1`.

## إعداد الاتصال بمزود نموذج

بعد فتح اللوحة، أضف اتصال المزود وعنوانه ومفتاحه من واجهة الاتصالات، ثم اختر نموذجًا وفريقًا/وكيلًا. لا تضع مفاتيح مزود النماذج داخل السكربتات أو المستودع. رمز الوصول المحلي للوحة منفصل عن مفاتيح مزودي النماذج، ويتغير عند كل تشغيل. إذا بدأت الجلسة دون اتصال نموذج مضبوط، يمكن استعراض إدارة المنصة لكن لن تنفذ طلبات نموذج سحابية.

## التشغيل اليدوي المتقدم

يمكن تشغيل الـAPI والواجهة يدويًا عند الحاجة؛ اضبط `DRAGONKMG_DB_PATH` بالقيمة نفسها في الطرفيتين كي يرى الـCLI واللوحة الجلسات ذاتها. في هذا الوضع يجب إنشاء `DRAGONKMG_LOCAL_API_TOKEN` عشوائيًا وإدخاله في اللوحة. المشغّل أعلاه يتولى إعداد هذه القيم المؤقتة تلقائيًا.

## حدود النسخة الحالية

هذه طريقة تشغيل من المصدر لتجربة فردية محلية وليست مُثبّتًا موقّعًا. PostgreSQL، استعادة النسخ الاحتياطية، وموفر هوية إنتاجي متعدد المستخدمين غير مكتملة. Windows هو النظام الذي يوفر حاليًا مخزن أسرار Windows DPAPI؛ macOS Keychain وLinux Secret Service موثقان كعمل لاحق. أبقِ الخدمة على `127.0.0.1`، ولا تفتح المنافذ على الشبكة ولا تستخدم بيانات حساسة قبل استكمال متطلبات الإنتاج ومراجعتها.
