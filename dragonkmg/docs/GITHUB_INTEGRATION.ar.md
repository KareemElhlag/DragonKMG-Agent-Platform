# ربط حساب GitHub والمستودعات الخاصة — تجربة محدودة للقراءة

## النطاق الحالي

الربط حساب واحد لكل تثبيت محلي، وليس هوية متعددة المستخدمين. واجهة الويب وCLI يستخدمان نفس الخدمة؛ يجب تحديد `DRAGONKMG_DB_PATH` نفسه لعرض نفس المشاريع والربط. لا يوجد OAuth أو GitHub App في هذه المرحلة.

أدخل **Fine-grained personal access token** يدويًا داخل حقل الربط المخفي؛ لا ترسله في الشات أو في سطر الأوامر. أنشئه من إعدادات GitHub، حدد المستودعات المطلوبة فقط، واختر أقل صلاحية مناسبة: **Metadata: Read-only**. لا تطلب صلاحيات الكتابة أو الإدارة. المستودعات الخاصة التابعة لمنظمة قد تحتاج موافقة المنظمة على الرمز قبل ظهورها. عيّن تاريخ انتهاء قصير للتجربة.

التخزين حاليًا Windows DPAPI للمستخدم الحالي فقط. الأنظمة الأخرى ترفض الربط حتى يتوفر OS Vault مناسب؛ لا يوجد fallback إلى environment أو ملف نصي. يتم التحقق من `/user` قبل حفظ الرمز. لا يرجع الرمز في أي استجابة أو سجل تدقيق. سجل الإدارة يحفظ المسار والنتيجة فقط.

## الاستخدام

من الشات افتح الإضافات ثم GitHub، اربط الحساب، اعرض المستودعات، وحدد مستودعًا للمشروع المختار. المشروع يبقى **مجلدًا محليًا مستقلًا**. الربط يحفظ اسم مستودع متاح فقط؛ لا يعمل clone أو تحميل ملفات أو إرسال سياق للنماذج، ولا يمنح أدوات للوكلاء.

داخل جلسة CLI:

```
/github connect
/github status
/github repos 1
/project cwd
/github use owner/repository
/github disconnect
```

`connect` يفتح إدخالًا محليًا مخفيًا بدون طباعة الرمز. لا تمرر الرمز بعد الأمر. عرض المستودعات 30 نتيجة لكل صفحة، بحد 100 صفحة. لا تدل قائمة فارغة وحدها على عدم وجود مستودعات؛ راجع تحديد المستودعات وموافقة المنظمة وانتهاء الرمز.

## الحماية والقيود

واجهات القراءة المحلية تعيد `GET /api/projects/{id}/github` بشكل `{binding: object|null}`؛ لا يُفسر غياب الربط كخطأ. حالة الحساب من`GET /api/integrations/github`، والإجراءات نفسها متاحة فيCLI عبر`/github`.

- طلبات HTTPS GET فقط إلى `api.github.com`، بدون اتباع تحويلات، مهلة 15 ثانية، وحد استجابة 512 KiB.
- لا تنفيذ git push أو كتابة issue أو تعديل مستودع؛ الربط ليس grant أو موافقة على أدوات مستقبلية.
- اختيار المستودع يتحقق من إمكانية قراءته ثم يحفظ الربط في SQLite مع readback.
- إعادة الربط برمز صالح تمسح روابط المستودعات السابقة قبل حفظه، لمنع تسريب أسماء مستودعات الحساب السابق؛ اختر المستودعات مجددًا. الرمز المرفوض قبل الحفظ لا يغير الربط القديم. إذا تعذر حفظ الرمز بعد مسح الروابط، تبقى العملية مغلقة وتحتاج إعادة اختيار الروابط.
- ترتبط صفوف المستودعات داخليًا ببصمة اعتماد غير معروضة. إذا انتهى طلب ربط قديم بعد تبديل الحساب من عملية CLI/API أخرى، لا تظهر بياناته مع الاعتماد الجديد ويُرفض readback بحالة `GitHubAccountChanged`. الروابط القديمة بلا نطاق اعتماد تُعامل كغير متاحة حتى إعادة الربط.
- فصل الحساب يحذف رمز DPAPI والروابط المحلية، **ولا يلغي الرمز لدى GitHub**؛ ألغِه من إعدادات GitHub عند عدم الحاجة إليه.
- انتهاء/سحب الرمز يظهر خطأ ويحتاج إعادة الربط؛ لا يوجد تجديد تلقائي أو retry غير محدود.
- القبول الهندسي مبني على اختبارات HTTP/Vault وهمية؛ تجربة حساب خاص حي تحتاج إدخال المستخدم رمزه يدويًا. لا تستخرج رموز GitHub من تطبيقات أخرى أو git credential manager.

السبرنت التالي: OAuth/GitHub App، vault متعدد الأنظمة، عزل حسابات المستخدمين، موافقات granular وأدوات ملفات/كتابة مستقلة عن هذا الربط.
